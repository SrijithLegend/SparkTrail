# SparkTrail

A **simulation** that traces how a cyber event on EV-charging / microgrid
infrastructure propagates into physical effects (temperature, current, voltage,
frequency) and renders the propagation path in 3D.

It never touches a real charger, backend, or vehicle. Everything is a software
model. An "attack" is an abstract event — *a bad value appears on this modelled
link at time T* — injected so you can observe and rank its physical
consequences. How a real attacker would obtain that access is out of scope by
design.

## Run it

```bash
pip install -r requirements.txt

# headless: one scenario -> trace.json + printed summary
python -m sparktrail.cli scenarios/dcfast_overcurrent_tempspoof.yaml

# build the compact timeline the 3D viewer replays (all scenarios)
python -m sparktrail.viz

# self-checks
python test_sparktrail.py

# live "chaos engineering" console (Phase 4) — optional deps
pip install -r requirements-app.txt
streamlit run app.py
```

The experience site (Next.js scrollytelling + live propagation graph) is in
`sparktrail-experience/`: `cd sparktrail-experience && npm install && npm run dev`.

The landing page is `landing/index.html` (static, scroll-driven story; serve the
repo root with `python -m http.server` so its "Launch the simulator" link resolves).

The 3D viewer is `viz3d/index.html`; it loads `viz3d/scenes.json` from the same
folder. Serve the folder (`cd viz3d && python -m http.server`) or open the
published artifact. Pick a **TARGET** then an **ATTACK** from the two menus
(49 pre-baked target×attack cells, generated by `python -m sparktrail.viz`),
including **DEFENDED** cells where the Zero-Trust proxy and sensor-fusion
validator catch the attack (green `BLOCKED` / `CAUGHT` stamps, `THREAT CONTAINED`).
Drag to orbit, scroll to zoom, **click a node to focus**, `⟲` to reset,
step/▶/speed on the transport bar. Retro-CRT skin (amber phosphor, scanlines).

## Coverage

**All 6 charger types** (`targets/charger.py`, one parametrized plugin):
AC Level 1, AC Level 2, DC fast, DC ultra-fast / HPC (liquid coolant node),
battery-buffered (buffer SoC), bidirectional / V2G (export).

**All 5 microgrid types** (`targets/microgrid.py`): single-feeder hub,
LV distribution (with PV), islanded (frequency via swing), microgrid with BESS,
campus/fleet depot.

**All 7 attack mechanisms** (`attacks/`): `command_override`, `sensor_spoof`,
`setpoint_drift`, `mass_command`, `dos_blackhole`, `replay`, `desync`.

**All 6 entry points**: `backend_link`, `vehicle_link`, `sensor_bus`,
`hub_controller`, `inverter_link`, `firmware_state`.

**All physical effects**: pack temp (true vs reported), coolant temp (HPC),
current, transformer load %, bus voltage % (under/overvoltage), frequency
(nadir / peak / RoCoF), BESS SoC, V2G export power.

## Defence (four ported phases)

On top of the attack/physics engine, four defensive layers (from the alternate
build) are wired in:

1. **Zero-Trust Physics Proxy** (`control/proxy.py`) — refuses an *authorized but
   dangerous* command: even a well-formed over-limit current or a dropped
   load-shed is clamped/restored and logged as a `control/reject`. Enable per
   scenario with `proxy: true`. Defended DC-fast overcurrent drops the pack from
   **57.7 °C → 43.2 °C**; defended mass command from **174 % → 104 %** load.
2. **Cross-Layer Sensor Fusion** (`monitor/sensor_fusion.py`) — closes the
   electrical↔thermal energy balance (Joule heating minus max cooling, evaluated
   at the *reported* temp). A held-low sensor can't move the reported rise, so it
   trips; an honest pack — even cooling hard, even at equilibrium — never does.
   Alerts only, debounced against current step-changes.
3. **Propagation depth** (`core/events.py`) — every event carries
   `propagation_depth` (hops from the root attack) and `source_node`;
   `node_depths()` feeds the viewer (root 0 / impact 1 / cascade 2+).
4. **Chaos console** (`app.py`) — Streamlit red-team UI: run any scenario with or
   without the proxy, watch the live defence log, hand-spoof a sensor against the
   fusion validator.

## How it's wired

- **Event store** (`core/events.py`) — one append-only log; `caused_by` links
  events into a propagation `networkx.DiGraph`. The trace *is* the product.
- **Plant vs. monitor separation** — the physics-aware monitor
  (`monitor/physics_aware.py`) runs a *different* R/C model and only alerts,
  never blocks; detection delay reported honestly.
- **Impact scoring** (`scoring/impact.py`) — ranks a scenario by physical effect
  (peak temp, load, voltage excursion, frequency excursion, speed, nodes).
- **3D tracer** (`viz3d/`) — Three.js scene: type-aware node shapes, link tubes,
  additive attack pulses, heat ramp, overload glow, islanded ring / PV / BESS
  decor, live gauges, timeline scrubber, `modelled`/`illustrative` flags.

## Multi-domain expansion (`sparktrail/domains/`, `viz3d/multidomain.html`)

The EV engine generalizes to the whole class of cyber-physical infrastructure
(`SPARKTRAIL_MULTIDOMAIN.md`). A `Domain` is a set of nodes + links, a few
consequence metrics, and a handful of **abstract-injection** scenarios.

```bash
python -m sparktrail.domains        # build viz3d/scenes/<domain>.json + index.json
cd viz3d && python -m http.server   # open multidomain.html
python test_domains.py              # domain self-checks
```

- **Six playable domains** (`domains/`): EV charging hub (wraps the real engine),
  power substation / feeder, water treatment, manufacturing robot cell (unoccupied),
  building HVAC / cold storage, pumping / pipeline station. OT / equipment only —
  the consequence lands on *process and equipment, never a human body* (§0).
- **Manipulation menu = MITRE ATT&CK for ICS categories** (`base.CATEGORIES`):
  push a setpoint out of range (T0836), freeze/fake a sensor (T0856), broadcast a
  mass command (T0831), suppress a protection signal (T0878), replay/delay (T0857).
  Each scenario is anchored to a **public incident** (Ukraine 2015/16, Oldsmar 2021,
  Colonial 2021, …). The "attack" is only an out-of-range value on a modelled link —
  no exploit, no protocol, no device command.
- **Uniform trace** → the viewer colours nodes by propagation depth (root red →
  cascade dim), climbs Nixie consequence meters to their red line, runs spark-trail
  beads along links, and shows **defended vs undefended** peaks side by side (proxy
  *prevents*; fusion *detects*).
- **§10 case-study gallery** — a cited "Prior Occurrences" wall (Stuxnet, Jeep,
  GPS spoofing, medical devices) proving the pattern generalizes. Human-harm domains
  are **cited, not simulated** — no mechanism, no harm animation.
- **3D models (§5):** nodes render from primitives with no downloads; drop a
  licence-clean `.glb` into `viz3d/models/<domain>/` and set the domain's
  `scene_models` to upgrade (see `viz3d/models/ATTRIBUTION.md`).

Multi-domain honest limits (say these first): every domain model is **lumped /
first-order** — directionally right, not engineering-accurate; the defenses share
the model's form so catch/block times are optimistic; domains are **archetypes**,
not any specific facility; the gallery is **reporting, not simulation**.

## Honesty in the UI
Every physical number is flagged `modelled` (from a real model) or
`illustrative` (hand-set). The monitor uses a *different* R/C from the plant,
so its detection time isn't faked by sharing the plant's model.

## Limits (by design)
- Lumped single-temperature battery model; no cell-level or spatial detail.
- Monitor shares the *form* of the plant model, so its detection is optimistic.
- Steady-state feeder math (algebraic); single-bus swing for frequency.
- Governor / droop constants are illustrative, hand-tuned (marked in code).
- Hardware thermal cut-offs / fuses modelled only as a firmware flag.
- Attack entry is "a wrong value on a link"; obtaining that access is out of scope.

## Stretch (interfaces are fixed, so these are drop-in)
- Swap models for PyBaMM (battery) / pandapower (grid), same `Target` interface.
- FastAPI WebSocket streaming instead of `scenes.json` replay (`api/server.py`).
- Monte-Carlo over ambient / impedance for an impact *distribution*.
